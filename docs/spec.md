# UnBin 実装仕様書

CD イメージを ISO (データ) と WAV (音声) に変換するときに、何を正しいとするかを決める文書。
前半 (§1〜§6) は CD とイメージ形式の事実の整理、後半 (§7〜§11) はこのアプリの仕様と、現在の実装との差分。

各項目の状態は次の印で示す。

| 印 | 意味 |
|---|---|
| 済 | 実装し、試験 (`tests/test.py`) か実物で確かめた |
| 一部 | 実装はあるが、仕様の一部を満たしていない |
| 未 | 未実装 |
| 対象外 | このアプリでは扱わない (理由を書く) |

出典が弱い、または実物で確かめていない事項は §12 にまとめた。実装の前に確かめること。

## 1. 目的と範囲

- 用途: CD イメージの中身を見る (データを ISO にして開く・マウントする) ことと、音楽トラックを WAV として取り出すこと。
  **元のディスクを再現するイメージを作る道具ではない** (その用途には元の cue + bin をそのまま使う)。この方針は 2026-11-21 に決めた。
- 入力: CD (CD-DA、CD-ROM、その派生) を読み取った cue + bin。ほかのイメージ形式は扱わない (§6.2)。
- 出力: データトラックごとの ISO、音声トラックごとの WAV。
- 目標: 出力した ISO が、元のディスクを直接読んだとき (`dd` などで論理セクタを読み出したとき) と同じ内容になり、macOS や他の OS でそのままマウントできること。
  ISO にすると失われる情報があるディスクでは、黙って欠落させず、利用者に知らせること。
- **実装はすべて独自に書く。** 既存のツールやライブラリ (AnyToISO、bchunk、libcdio、libmirage、cdrdao など) のソースコードは、
  ライセンスにかかわらず流用せず、写しも翻案もしない。形式の根拠にするのは、公開された規格、形式を説明した文書、実物のイメージを自分で調べた結果とする。
  他の実装のソースは読まずに済ませ、文書で分からないことは実物で確かめる。外部のライブラリにも依存しない (macOS 標準のフレームワークは使う)。
- 対象は CD のみ。DVD・BD (1 セクタ 2048 バイトで生セクタの概念が無く、イメージは最初から ISO) と、CD 以外の独自ディスクは扱わない。

## 2. CD の基礎

### 2.1 単位

| 用語 | 内容 |
|---|---|
| セクタ (フレーム) | CD の読み出し単位。2352 バイト。1 秒 = 75 セクタ |
| MSF | 分:秒:フレーム (フレームは 0〜74)。cue の INDEX はこの書き方 |
| LBA | 論理ブロック番号。プログラム領域の先頭 (MSF 00:02:00) が LBA 0。`LBA = (分×60 + 秒)×75 + フレーム − 150` |
| トラック | 1〜99。種類は音声かデータ。制御ビットで区別する |
| インデックス | トラック内の区切り。INDEX 01 がトラックの開始。INDEX 00〜01 はプリギャップ |
| セッション | リードイン・プログラム領域・リードアウトの 1 組。CD-R の追記や CD Extra で複数になる |
| サブチャンネル | 1 セクタに 96 バイト (P〜W の 8 本)。Q に位置・ISRC・カタログ番号、R〜W に CD+G・CD-TEXT |

- 74 分の CD は 333,000 セクタ、80 分は 360,000 セクタ。
- 1 枚目のトラックの前には必ず 150 セクタ (2 秒) のプリギャップがある (LBA −150〜−1)。イメージには普通入らない。
- 種類の違うトラック (データと音声) が隣り合うときは、間に 150 セクタ以上のプリギャップが入る。

### 2.2 規格 (レインボーブック)

| 通称 | 対象 | 公開規格 | 要点 |
|---|---|---|---|
| Red Book | CD-DA (音楽 CD) | IEC 60908 | 44.1kHz・16 ビット・ステレオ。1 セクタ = 588 サンプル |
| Yellow Book | CD-ROM | ECMA-130 (ISO/IEC 10149) | モード 1・モード 2 のセクタ形式 |
| CD-ROM XA | Yellow Book の拡張 | — | モード 2 にフォーム 1・フォーム 2 を定義。サブヘッダ 8 バイト |
| Green Book | CD-i | — | モード 2 フォーム 1/2。独自のファイルシステム |
| Orange Book | CD-R・CD-RW | — | 追記とマルチセッション |
| White Book | Video CD | — | XA。トラック 1 が ISO 9660、トラック 2 以降が MPEG (フォーム 2) |
| Blue Book | CD Extra (Enhanced CD) | — | セッション 1 が音声、セッション 2 がデータ |
| Beige Book | Photo CD | — | XA、マルチセッション |
| — | ファイルシステム | ECMA-119 (ISO 9660)、ECMA-167/UDF | ボリュームとディレクトリの構造 |

### 2.3 セクタの形式 (2352 バイトの内訳)

| 形式 | 0〜11 | 12〜15 | 16〜 | 利用者データ | その後 |
|---|---|---|---|---|---|
| 音声 | — | — | — | 2352 (位置 0) | — |
| モード 0 | 同期 | ヘッダ | — | 2336 (すべて 0) | — |
| モード 1 | 同期 | ヘッダ | — | 2048 (位置 16) | EDC 4、予約 8、ECC 276 |
| モード 2 (フォームなし) | 同期 | ヘッダ | — | 2336 (位置 16) | — |
| モード 2 フォーム 1 (XA) | 同期 | ヘッダ | サブヘッダ 8 | 2048 (位置 24) | EDC 4、ECC 276 |
| モード 2 フォーム 2 (XA) | 同期 | ヘッダ | サブヘッダ 8 | 2324 (位置 24) | EDC 4 (0 のこともある) |

- 同期は `00 FF FF FF FF FF FF FF FF FF FF 00`。ヘッダは MSF 3 バイト (BCD) とモード 1 バイト。
- サブヘッダは「ファイル番号・チャンネル番号・サブモード・符号化情報」の 4 バイトを 2 回繰り返す。
  サブモードのビット: 0x01 レコード終端、0x02 映像、0x04 音声、0x08 データ、0x10 トリガ、**0x20 フォーム 2**、0x40 実時間、0x80 ファイル終端。
- EDC は CRC-32 (多項式 `(x^16+x^15+x^2+1)(x^16+x^2+x+1)`、反転表現 0xD8018001)。計算範囲はモード 1 が 0〜2063、フォーム 1 が 16〜2071、フォーム 2 が 16〜2347。
- ECC はリード・ソロモン積符号 (P 172 バイト + Q 104 バイト)。フォーム 1 ではヘッダ 4 バイトを 0 とみなして計算する。
- イメージによっては 2352 バイトの後ろにサブチャンネル 96 バイトが付き、1 セクタ 2448 バイトになる。

## 3. 「ISO ファイル」の定義

**ISO ファイルそのものを定めた正式な規格は無い。** ISO 9660 (ECMA-119) が定めるのはディスク上のボリュームの構造で、ファイルとしての「.iso」は
「データトラックの論理セクタ (利用者データ 2048 バイト) を LBA の順に並べたもの」という慣習である。中身のファイルシステムは ISO 9660 に限らず、HFS や UDF でもよい。

このアプリでは、次を満たすものを正しい ISO とする。

1. 大きさが 2048 バイトの倍数である。
2. ファイルの n 番目の 2048 バイトが、ボリュームの論理セクタ n の利用者データと一致する。
   ファイルシステムは絶対 LBA でディレクトリやファイルの位置を持つので、**ファイルの先頭がボリュームの LBA 0 に当たらなければマウントできない** (§5.2)。
   LBA 0 より後ろから始まるトラックでは、前を空きで埋め、ボリューム記述子の写しを LBA 16 に置く。
3. 利用者データは取り出すだけで、書き換えない (ボリューム記述子や名前を直さない)。
4. ISO 9660 のボリュームであれば、主ボリューム記述子が示すボリュームの大きさ (論理ブロック数) 以上の長さがある。

この定義から、次が決まる。

- 音声は ISO に入らない (論理セクタではない)。音声だけの CD からは ISO を作らない。
- フォーム 2 のセクタ (2324 バイト) は ISO に入らない。Video CD のようにフォーム 2 を使うディスクは、ISO にすると動画・音声の部分が欠ける (§5.3)。
- サブチャンネル、EDC/ECC、プリギャップ、トラックの境界、CD-TEXT、ISRC は ISO に入らない。元の cue + bin を捨てると戻せない。

| 音楽 CD (CD-DA) | 全トラックが音声 | WAV をトラックごと。ISO は作らない | 済 | ISO を作れないことは表示する。プリエンファシス・隠しトラックは §5.4 |
| ミックスモード CD | トラック 1 がデータ、2 以降が音声 | ISO 1 本 + WAV | 済 | 音声は ISO の外になる |

| マルチセッションのデータ CD | セッションごとにデータトラック | 全セッションを並べ、最後のセッションを基準にした ISO 1 本 | 済 (合成イメージのみ) | 後のセッションが前のセッションのファイルを参照する (§5.2) |

| CD-ROM XA (フォーム 1 のみ) | モード 2 フォーム 1 | ISO 1 本 | 済 | — |
| Video CD・SVCD | トラック 1 が ISO 9660、2 以降がフォーム 2 の MPEG | トラック 1 の ISO。MPEG は別扱い | 一部 (警告は済、MPEG の書き出しは未) | フォーム 2 は ISO にできない (§5.3) |
| Photo CD | XA、マルチセッション | ISO | 済 (合成イメージのみ) | マルチセッションと同じ |

| CD+G (カラオケ) | 音声 + サブチャンネルの画像 | WAV。画像は `.cdg` | 一部 | 音声は取り出せる。画像 (`.cdg`) の書き出しは未 |
| フォーム 1 とフォーム 2 が混在する CD-ROM XA | モード 2。音声トラックを持つものもある | ISO (欠落の警告付き) + WAV | 済 (合成イメージのみ) | フォーム 2 の部分 (動画・音声) が欠ける (§5.3) |
| 誤りセクタのある CD | EDC の合わないセクタ、同期信号の無いセクタ | ISO (誤りの報告付き) | 済 (合成イメージのみ) | その部分のデータは正しくない可能性がある |

## 5. 取り出しの規則

### 5.1 データセクタ

| 規則 | 状態 |
|---|---|
| 2352 バイトのセクタは、同期とヘッダのモードを見て利用者データの位置を決める (モード 1 は 16、モード 2 は 24)。同期が無ければ入力形式の宣言に従う | 済 |
| 2336 バイトのセクタ (同期とヘッダが無いモード 2) は位置 8 から 2048 バイト | 済 |
| 2048 バイトのセクタはそのまま写す | 済 |
| 2448 バイトのセクタは、後ろの 96 バイト (サブチャンネル) を捨てて 2352 と同じに扱う | 済 |
| モード 2 ではセクタごとにサブヘッダを見て、フォーム 2 (2 回の繰り返しが一致し、サブモードに 0x20) を数える。1 つでもあれば §5.3 の扱いにする | 済 |
| 同期の無いセクタは、宣言されたモードの位置から 2048 バイトをそのまま写し、数を報告する (中身は変えない) | 済 |
| トラックの長さがセクタの大きさで割り切れないときは、端数を捨てて報告する | 済 |
| トラック末尾のポストギャップ (中身が 0 のセクタ、普通 150 個) は捨てずに残す。ドライブから直接読んだ ISO と同じ長さになる | 済 |

### 5.2 LBA 0 から始まらないデータトラック

ISO 9660 のディレクトリやファイルの位置は、ディスクの先頭からの絶対 LBA で書かれている。
セッション 2 のデータトラック (CD Extra) を単純に取り出すと、ファイルの先頭がボリュームの LBA 0 ではなくなり、マウントできない。
さらに、ボリューム記述子はセッションの先頭から 16 セクタ目にある。実物のディスクでは OS が TOC から最後のセッションの位置を知って読みに行くが、
イメージのファイルにはその情報が無いので、OS はファイルの 16 セクタ目しか見ない。

データトラックがディスクの LBA `S` (`S > 0`) から始まるとき、既定では次の ISO を書く (位置合わせ)。

1. 先頭に `S` セクタ分の空きを入れ、その後ろにトラックの利用者データを置く。空きはスパースにして、実際のディスク使用量は増やさない。
2. 空きの LBA 16 以降に、トラックのボリューム記述子の並び (トラックの 16 セクタ目から終端記述子まで) の写しを置く。トラックのデータそのものは書き換えない。

位置合わせをしない取り出し (トラックの利用者データだけ) も選べる (GUI のチェックボックス、コマンドラインの `--no-align`)。

`S` の決め方。主ボリューム記述子のルートディレクトリの LBA を `R` とし、ルートディレクトリの先頭の記録 (`.`) が自分自身の LBA `R` を持つことを使って確かめる。

1. トラックの `R` セクタ目がルートディレクトリなら、ボリュームはトラックの先頭を LBA 0 として作られている。位置合わせはしない。
2. cue から計算した `S` について、トラックの `R − S` セクタ目がルートディレクトリなら、その `S` を使う。
3. どちらでもなければ、トラックの 17〜4095 セクタ目からルートディレクトリを探し、見つかった位置 `n` から `S = R − n` とする (cue にセッションの情報が無くても決まる)。
4. 見つからず、cue の計算では `S > 0` のときは、位置合わせをせずに警告する。
5. ISO 9660 のボリュームでないトラック (独自のファイルシステムなど) は位置合わせをしない。

cue からの `S` の計算:

- 同じ bin の中では INDEX の値。bin が分かれているときは、前のファイルの長さを足し合わせる。
- `PREGAP`・`POSTGAP` (ファイルに無いギャップ) の長さを足す。
- セッションが変わるところ (`REM SESSION nn`) では、リードアウト 6750 + リードイン 4500 + プリギャップ 150 = **11400 セクタ** を足す
  (3 つ目以降のセッションは 2250 + 4500 + 150 = 6900)。`REM LEAD-OUT`・`REM LEAD-IN`・`REM PREGAP` があれば、その合計を代わりに使う。

状態: 済 (合成イメージ。位置合わせした ISO が macOS でマウントでき、中のファイルが一致することを `tests/mount_check.py` で確かめた)。
実物の CD Extra のイメージでは確かめていない。

マルチセッションのデータ CD (後のセッションが前のセッションのファイルを参照する) は、全セッションを絶対 LBA の位置に並べた 1 本の ISO
(`<名前>.iso`) にし、最後のセッションの記述子の写しを LBA 16 に置く (実物のドライブが最後のセッションを見せるのと同じ)。まとめる条件:

- データトラックが 2 本以上あり、どれも上の方法で位置を確かめられた ISO 9660 のボリュームである。
- 各トラックの範囲 (`S` 〜 `S` + 長さ) が重ならず、cue の順に並ぶ。
- 最後のセッションの記述子を置く LBA 16 以降の場所が、前のセッションの記述子か、0 で埋まったセクタである (ほかのデータを潰さない)。

条件に合わなければ、これまでどおりトラックごとの ISO にする。位置合わせを切ったとき (`--no-align`) もトラックごとになる。

状態: 済 (合成イメージ)。実物のマルチセッションのイメージと、まとめた ISO のマウントは確かめていない。

### 5.3 フォーム 2 を含むトラック

- フォーム 2 のセクタは利用者データが 2324 バイトで、2048 バイトの並びに入らない。ISO では、その位置に **先頭 2048 バイトを置く** (多くの変換ツールと同じ。位置がずれないので、フォーム 1 の部分にあるファイルシステムは読める)。
- フォーム 2 が 1 つでもあれば、「この ISO では動画・音声のデータが欠ける。完全な写しには元の cue + bin を残すこと」と、欠けるセクタの数を表示する。変換は止めない。
- Video CD の MPEG トラック (全体がフォーム 2) は ISO にしない。2324 バイトずつ取り出した MPEG の並び (`.mpg`) として書き出す選択肢を付ける。

状態: 先頭 2048 バイトを置くことと警告は済 (読み込んだ時点で全セクタを調べ、一覧に出す)。MPEG の書き出しは未。

### 5.5 ファイルシステムの判別 (表示と検証のため。取り出しには使わない)

すべて利用者データ上の位置。

| 種類 | 見分け方 |
|---|---|
| ISO 9660 | セクタ 16 以降の記述子の 1〜5 バイト目が `CD001`。種類は 0 バイト目 (0 ブート、1 主、2 副、255 終端)。主記述子の 40〜71 がボリューム名、80〜87 が論理ブロック数 (両エンディアン)、128〜131 がブロックの大きさ |
| High Sierra (ISO 9660 の前身) | セクタ 16 の 9〜13 バイト目が `CDROM` |
| Joliet | 副記述子 (種類 2) の 88〜90 バイト目が `25 2F 40`・`25 2F 43`・`25 2F 45`。名前は UCS-2 (ビッグエンディアン) |
| Rock Ridge | ルートディレクトリの `.` の記録のシステム使用領域が `SP` (SUSP) で始まり、`RR`・`PX`・`NM` などを持つ |
| El Torito (起動 CD) | セクタ 17 が種類 0 で、7 バイト目から `EL TORITO SPECIFICATION` |
| UDF (ブリッジ) | セクタ 16 以降の並びに `BEA01`・`NSR02` か `NSR03`・`TEA01`。アンカーは LBA 256 |
| Apple パーティションマップ | 先頭 2 バイトが `ER` (0x4552)、512 バイト目 (または 2048 バイト目) から `PM` (0x504D) の項目 |
| HFS / HFS+ | 1024 バイト目が `BD` (0x4244) / `H+` (0x482B)。パーティションマップがあれば各区画の先頭から 1024 バイト目 |
| ハイブリッド | ISO 9660 と、パーティションマップか HFS の両方がある |

状態: 済。`hdiutil` で作った本物の ISO 9660 + Joliet + Rock Ridge + HFS+ のハイブリッドと UDF ブリッジのイメージ、合成した El Torito・HFS・パーティションマップで確かめた。High Sierra は実物でも合成でも試していない。

## 6. 入力形式

### 6.1 cue + bin

cue シートは CDRWIN が始めたテキスト形式で、仕様は CDRWIN の利用者ガイドの付録が事実上の基準。

| 命令 | 扱い | 状態 |
|---|---|---|
| `FILE "名前" 種類` | `BINARY` (リトルエンディアン)・`MOTOROLA` (ビッグエンディアン) | 済 |
| | `WAVE`・`AIFF`・`MP3` など、音声ファイルを指すもの | 対象外 (すでに音声ファイルになっていて、取り出すものが無い)。誤りとして断る |
| `TRACK nn 種類` | `AUDIO`・`MODE1/2048`・`MODE1/2352`・`MODE2/2336`・`MODE2/2352` | 済 |
| | `CDI/2336`・`CDI/2352` (モード 2 と同じ扱い) | 済 |
| | `CDG` (音声 + サブチャンネル、2448 バイト) | 済 (音声のみ) |
| | `MODE2/2048`・`MODE2/2324` (仕様外だが使われる) | 一部 (2048 は写すだけで通る。2324 は断る) |
| `INDEX nn mm:ss:ff` | 00 と 01 を使う。02 以降は無視 | 済 |
| `PREGAP`・`POSTGAP` | ファイルに無いギャップの長さ。取り出しには使わず、LBA の計算 (§5.2) に使う | 済 |
| `FLAGS` | `PRE` (プリエンファシス)・`DCP`・`4CH`・`SCMS`。`PRE` は案内、`4CH` は警告を出す | 済 |
| `CATALOG`・`ISRC`・`TITLE`・`PERFORMER`・`SONGWRITER`・`CDTEXTFILE` | 読み飛ばす | 済 |
| `REM` | セッションを書き表す `REM SESSION nn`・`REM LEAD-OUT`・`REM LEAD-IN`・`REM PREGAP` を読む。ほかは無視 | 済 (書き方は未確認、§12) |

- 文字コードは UTF-8、だめなら Shift-JIS として読む。改行は LF・CRLF のどちらも受ける。(済)
- bin の探し方: cue のフォルダからの相対パス、無ければファイル名だけを大文字小文字を無視して探す。(済)
- bin のプリギャップの持ち方には 2 通りある。トラックごとに bin を分ける形式はプリギャップを次のトラックのファイルの先頭に置き `INDEX 00` で示す。
  古い CDRWIN 式は 1 本の bin の中で `INDEX 00` と `INDEX 01` を並べる。どちらも INDEX 01 から取り出せば同じ結果になる。(済)

### 6.2 そのほかの形式 (対象外)

入力は cue + bin だけにする。用途 (§1) に対して、ほかの形式を読む利点が小さいため。

| 形式 | 扱わない理由 |
|---|---|
| CD コピーソフト各社の独自形式 (記述子 + 生イメージの組、1 ファイルにまとめたもの) | 公式の仕様が無く、独自に実装するには実物の解析が要る。出回りも減っている |
| cdrdao (`.toc` + `.bin`) | 利用者が少ない |
| 圧縮されたイメージ (`.ecm`、`.isz` など) | 伸長の実装が要り、外部の依存を持たない方針と合わない |
| Mac のイメージ (`.cdr`・`.toast`・`.dmg`) | `.cdr` (ディスクユーティリティの「CD/DVD マスター」) とデータだけの `.toast` は 2048 バイトの並びで、ISO と同じ。変換は要らない。`.dmg` は `hdiutil` の仕事 |
| cue の無い bin 単体 | cue が無いとトラックの境界が分からない。データ 1 トラックと仮定して読むことはできるが、今は扱わない |

## 7. 出力

### 7.1 ISO

- §3 の定義に従う。1 セクタずつ利用者データ 2048 バイトを書く。
- 位置合わせ (§5.2) の空きはスパースにする。(済)
- 書きかけは一時的な名前 (`<出力名>.part`) で書き、終わってから名前を変える。失敗・中止したら消す。WAV も同じ。(済)

### 7.2 WAV

- RIFF/WAVE、`fmt ` 16 バイト (PCM、2 チャンネル、44100Hz、16 ビット)、`data`。ヘッダは 44 バイト。(済)

### 7.3 ファイル名

| 出力 | 名前 | 状態 |
|---|---|---|
| データトラックが 1 本 | `<名前>.iso` | 済 |
| データトラックが複数 | `<名前> (Track NN).iso` | 済 |
| マルチセッションをまとめたとき (§5.2) | `<名前>.iso` | 済 |
| 音声トラック | `<名前> (Track NN).wav` | 済 |
| 隠しトラック | `<名前> (Track 00).wav` | 済 |
| フォーム 2 の MPEG | `<名前> (Track NN).mpg` | 未 |
| CD+G の画像 | `<名前> (Track NN).cdg` | 未 |

- 出力が入力のファイルと同じパスになるときは変換しない。(済)
- 同じ名前のファイルがあれば、上書きの前に確かめる。コマンドラインは変換せずに終わり、`--force` を付けたときだけ上書きする。(済)

### 7.4 cue の作り直し (対象外)

出力した ISO と WAV を指す cue を書けば、分けた後も 1 枚のディスクとして扱える。中身を見る・音楽を取り出すという用途 (§1) には要らないので作らない。

## 8. 検証

変換のときに調べ、結果を一覧と完了の表示に出す。変換は止めない (止めるのは §9 の誤りだけ)。

| 検査 | 内容 | 状態 |
|---|---|---|
| セクタの整合 | 同期があること | 済 |
| | ヘッダの MSF が連番であること、モードが宣言と合うこと | 未 |
| EDC | 2352・2336 バイトのデータセクタで EDC を計算して照合し、合わないセクタの数と最初の位置を出す。フォーム 2 で EDC が 0 のものは検査しない | 済 (モード 1 は実物の CD の 129,397 セクタで全数一致) |
| ECC での訂正 | EDC が合わないセクタを P/Q で訂正する | 対象外 (検出して知らせるまで。訂正は復元ツールの仕事) |
| ボリュームの大きさ | ISO 9660 なら、主記述子の論理ブロック数 × ブロックの大きさ ≦ ISO の大きさ。足りなければ「イメージが途中で切れている」と警告 | 済 |
| 位置合わせ | §5.2 の確かめ | 済 |
| ファイルシステム | §5.5 の判別の結果 (ISO 9660 / Joliet / Rock Ridge / El Torito / UDF / HFS / ハイブリッド / 不明) | 済 |
| 音声 | トラックの長さが 2352 の倍数であること。全サンプルが 0 のトラック、データセクタの同期を持つ「音声」トラック (種類の宣言の誤り) | 未 |

## 9. 誤りと警告

変換を止める誤り:

| 条件 | 状態 |
|---|---|
| cue にトラックが無い、`TRACK` の前に `FILE` が無い | 済 |
| bin が見つからない、bin が cue の示す長さより短い | 済 |
| 対応していない `FILE` の種類・セクタの大きさ | 済 |
| 出力が入力のファイルと同じパスになる | 済 |
| 保存先に書けない、空きが足りない | 一部 (空きの事前確認が無い) |

変換は続け、利用者に知らせる警告:

| 条件 | 状態 |
|---|---|
| 音声だけのディスクで ISO を作れない | 済 |
| フォーム 2 を含み、ISO ではデータが欠ける | 済 |
| データトラックが LBA 0 から始まらず、位置合わせをした (または、できなかった) | 済 |
| EDC の合わないセクタ、同期の壊れたセクタがある | 済 |
| ボリュームの大きさに対してイメージが短い | 済 |
| ファイルシステムを判別できない (独自のファイルシステムなど。取り出しは正しい) | 済 (警告ではなく「ファイルシステム不明。取り出しはできます」と表示) |
| プリエンファシス付きの音声、4 チャンネルの音声 | 未 |
| トラックの長さがセクタの大きさで割り切れない | 済 |

## 10. 現在の実装との差分

データだけの CD-ROM、音楽 CD、ミックスモード CD、HFS やハイブリッドの CD、CD Extra、マルチセッションのデータ CD は仕様どおりに変換できる。残っている差は次のとおり。影響の大きい順。

| 差分 | 影響 | 節 |
|---|---|---|
| ヘッダの MSF の連番の検査、音声トラックの検査が無い | 一部の壊れ方に気付けない | §8 |

## 11. 実装の順序 (案)

1. **不具合の修正と警告**: `CDG` の扱い、フォーム 2 の検出と警告、音声だけのディスクの案内、端数の報告。(済、2026-11-21)
2. **位置合わせ**: `PREGAP`・`POSTGAP`・`REM SESSION` を読み、絶対 LBA を計算して §5.2 を実装。合成した CD Extra のイメージで試験。(済、2026-11-21。マルチセッションのデータ CD は残る)
3. **検証**: EDC の表と検査、ボリュームの大きさ、ファイルシステムの判別 (HFS・ハイブリッド・Joliet・El Torito・UDF)、結果の表示。(済、2026-11-21)
4. **マルチセッションのデータ CD**: 全セッションを絶対 LBA の位置に並べた 1 本の ISO にする (§5.2)。(済、2026-11-21)
5. **音声**: プリエンファシスの表示 (`FLAGS PRE`)、隠しトラックの書き出し。(済、2026-11-21)
6. **仕上げ**: `.part` での書き出し、コマンドラインでの上書きの確認。(済、2026-11-21)

2026-11-21 に用途を絞り (§1)、cue + bin 以外の入力形式、音声ファイルを指す cue、cue の作り直し、ECC での訂正を対象外にした。

## 13. 既存のツール (2026-11 の調査)

このアプリの立ち位置を決めるための整理。価格と対応は検索結果の記載によるもので、実際に動かして確かめてはいない。

| ツール | 環境 | 形態 | 備考 |
|---|---|---|---|
| WinBin2Iso | Windows | 無償、GUI | 小さな単機能ツール。Windows で最もよく挙がる |
| PowerISO・UltraISO・MagicISO | Windows | 有償 (試用版に制限) | 多形式の変換。MagicISO は更新が止まっている |
| AnyToISO | Windows・macOS | 無償版に大きさの制限 | BIN・MDF・NRG・CDI・IMG など多形式 |
| bchunk (binchunker) | macOS・Linux | 無償、コマンドライン | Homebrew・MacPorts で入る。cue + bin → ISO・WAV。このアプリと同じ仕事 |
| BchunkX | 旧 Mac OS X | 無償、GUI | bchunk の GUI。古い。macOS 27.2.1 では起動時に警告が出て、設定から許可すると起動する。bin と cue を 1 つずつ選ばせる作りで、トラックごとに bin が分かれたイメージを渡すと異常終了した (2026-11 に確認。原因は未確認) |
| XustoISO | macOS | 有償 (App Store) | 多形式の変換 |
| Disk Image Toolbox・Smart Disk Image Utilities | macOS | App Store | イメージの管理・書込。cue + bin → ISO の可否と価格は未確認 |

macOS では「無償・GUI・今の OS で動く」cue + bin の変換ツールが見当たらず、無償の選択肢は実質 bchunk (コマンドライン) だけである。
bchunk との違いにしたい点は、GUI のほかに §5.2 の位置合わせ、§5.3 のフォーム 2 の警告、§8 の検証 (bchunk はどれも行わない、と記憶している。要確認)。
